# Domain Docs

This is a single-context repository.

Before planning or implementing work:

1. Read `CONTEXT.md` for the project's canonical language.
2. Read relevant decisions in `docs/adr/`.
3. Use the glossary terms in issue titles, specs, ticket descriptions, and test names.
4. Surface conflicts with an ADR before changing the decision.

`CONTEXT.md` is a glossary and domain boundary document, not an implementation plan. Add new terms there when the project resolves a genuinely new concept. Use ADRs for hard-to-reverse architectural choices and meaningful trade-offs.
